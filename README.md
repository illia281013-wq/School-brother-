# AI School Assistant

Многостраничный учебный сайт для 5–11 классов. Интерфейс — HTML/CSS, интерактивность — JavaScript, AI API — Node.js + Express.

## Разделы
- Главная и школьные предметы.
- Учебный чат с выбором модели и класса.
- Разбор задания по фотографии.
- Каталог AI-моделей.
- Библиотека формул и правил.
- Настройки подключения сервера и Inworld TTS.

## Локальный запуск

Нужен Node.js 20+.

```bash
npm install
cp .env.example .env
# Заполни серверные ключи в .env
npm run dev
```

Открой http://localhost:5173. Vite проксирует `/api` на Express (порт 3001).

## Переменные окружения

- `OPENROUTER_API_KEY` — серверный ключ для учебного AI-чата и анализа фото.
- `INWORLD_API_KEY` — серверный ключ для озвучки.
- `INWORLD_TTS_VOICE_ID` — голос Inworld, по умолчанию Ashley.
- `VITE_API_BASE_URL` — адрес API, встраивается в клиент при сборке. Локально оставь `/api`.
- `APP_URL` и `FRONTEND_ORIGINS` — разрешённые адреса фронтенда для CORS.

**Никогда не добавляй секреты с префиксом `VITE_` и не помещай ключи в HTML/JS.** Не коммить файл `.env`.

## Развёртывание

Сайт и API — две отдельные части, если используется GitHub Pages или другой статический хостинг.

1. Разверни Node.js backend на сервере, который поддерживает запуск Express.
2. В настройках backend задай `OPENROUTER_API_KEY`, `INWORLD_API_KEY`, `APP_URL` и при необходимости `FRONTEND_ORIGINS`.
3. Для сборки фронтенда укажи адрес API, например:

```bash
VITE_API_BASE_URL=https://your-api.example.com/api npm run build
```

4. Опубликуй содержимое папки `dist` на статическом хостинге.

**Важно:** GitHub Pages сам по себе не запускает Express и не выполняет `/api/chat`, `/api/models` или `/api/tts`. Если фронтенд опубликован на GitHub Pages, но отдельный backend не развёрнут и `VITE_API_BASE_URL` не настроен на его адрес, AI-чат, анализ фото и озвучка не будут работать. Успешная сборка Pages не означает, что AI API доступен.

Для запуска всего приложения на одном Node.js-хостинге:

```bash
npm run build
npm start
```

## Проверки

```bash
npm test
npm run build
```

Тесты проверяют серверные валидаторы, базовые API-ошибки, CORS и обработку некорректных запросов. Для проверки реального ответа AI и синтеза Inworld нужны действующие серверные ключи. Перед релизом дополнительно проверь интерфейс в браузере на телефоне и компьютере.

## Данные и безопасность

- API-ключи хранятся только в серверном окружении.
- История чата хранится в localStorage текущего браузера.
- Загруженное изображение отправляется выбранному AI-провайдеру.
- Supabase не изменяется этой версией приложения.
